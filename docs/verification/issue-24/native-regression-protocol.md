# Native前版比較の固定条件（2026-10-18）

> 現在の正式比較には[復旧後の基準](recovered-native-baseline.md)を使う。
> 以下の初回数値表は再接続前の履歴であり、新しい3反復とは混合しない。
> 同一sourceを再測定する手順と新しい上限は、採用版の測定前にcommitしている。

[元の測定契約](performance-protocol.md)の20%回帰判定に、初めて揃ったnative3反復を使う。
比較前版はlocal `b4514b9c467184cdf2cbfdd444223883ee698fcf`、同じfixture SHA-256
`681be52e24ef0a1f9e8e7992fba6d1c8e2671acb9426525da231acc47d186252`。
この前版は挿入Hard未達で保留した版であり、受入済みとは扱わない。全rawをGit外に保存する。

各操作は3反復それぞれの5 warm-up＋20 measured値からnearest-rank p95を算出し、
**3 p95の最大値**をその操作の比較値にする。候補版も同じ3反復の最大値を使い、
前版比較値×1.20を超えた操作が1つでもあれば受入を止める。Hardも独立に全反復で判定する。
反復/sampleの省略、外れ値の除外、p95のpooling、中央値への置換を行わない。
候補版の正式3反復より前に、この比較法と全7操作の上限を固定する。

| 操作             | 前版の全3 p95 ms                 | 前版比較値 ms | 20%上限 ms |
| ---------------- | -------------------------------- | ------------: | ---------: |
| prop             | 62.019327, 70.215388, 74.790162  |     74.790162 |  89.748194 |
| insert           | 101.072864, 37.176080, 36.981725 |    101.072864 | 121.287437 |
| move             | 72.587398, 32.308007, 40.324875  |     72.587398 |  87.104878 |
| undo             | 2.402112, 2.285897, 2.465679     |      2.465679 |   2.958815 |
| native-roundtrip | 33.401576, 31.271616, 40.873632  |     40.873632 |  49.048358 |
| tsx-export       | 9.258856, 11.748579, 12.854066   |     12.854066 |  15.424879 |
| host-resolution  | 0.765547, 0.758396, 0.720298     |      0.765547 |   0.918656 |

独立auditorはfixture/規模/Node/CPU/回数/予算と前版のp95/maxを再検査してから比較する。
候補版は元の95 Hard条件に加えてこの7比較を満たす必要がある。
browser/独立CLIには比較可能な全3反復の前版がないため、そちらの20%回帰は未判定と記録する。

## 実行環境の再接続後の比較（測定前の補足）

上表は再接続前の原結果として保持する。実行サービスの再接続でPID namespaceが
更新され、旧boot IDは未記録だった。同じCPU名/OS/quotaだけでは、旧数値と同一の
実行instanceを証明できない。最初は旧上限を保守的に適用したが、採用前に比較条件を揃える。

比較sourceは同じ`b4514b9c467184cdf2cbfdd444223883ee698fcf`を維持する。
原3反復で生成したnative API bundleはすべてSHA-256
`9bd2ce7797448c3818cdba8a3acbc2332edc705e3d6b448125149ee54fd9b8cd`で一致する。
この未変更bundleを復旧後のinstanceで3 fresh process再実行し、その後に候補版を測る。
計測本体は当時と現行でbyte一致するdriver（SHA-256
`d8c7df0b321cbf369d03ee17a9d5d00c9ac66eb19f5425e3317d8bc6c56ae4a9`）を使う。
replayでは計測外のbundle読込とsource metadataだけを変更し、計測本体のbyte一致を検査する。

Hard、各5+20 sample、全3反復、3 p95最大の20%比較を変えない。旧raw/旧比較FAILを
消去・混合せず、再測定の全7基準値を[復旧後の基準](recovered-native-baseline.md)へ
記録・commitしてから候補版の正式測定を始める。前後のboot IDとbundle/fixture/driverの
一致を確認する。browser/CLIの比較可能な前版は引き続きなく、20%回帰は未判定。
