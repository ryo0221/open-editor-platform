| Situation | License / result |
| --- | --- |
| Private personal development and internal use | AGPL; generally no public source release for purely internal copies |
| Corporate internal deployment | AGPL; confirm whether any users receive copies or interact with modified software remotely |
| Selling documents, videos, designs or code created with the Editors | AGPL does not attach to outputs solely because the program produced them |
| Paid software distribution compliant with AGPL | Permitted; no OEM fee is owed by reason of sale |
| Paid hosted editing service satisfying AGPL §13 and other terms | Permitted; no OEM fee owed solely due to revenue |
| Distribution with closed-source integration inconsistent with AGPL | Separate commercial/OEM grant needed |
| Proprietary plugin using documented APIs | Possible only if genuinely separate or covered by a valid additional permission; see draft exception |
| Private changes to platform | AGPL; no universal obligation to publish to GitHub |
| Copies lawfully obtained under the prior MIT release | Continue under their earlier MIT grant |

An AGPL source offer is made to the legally specified recipients/network users and must cover the correct corresponding source. Publishing a repository is one way to provide source but is not always required or sufficient.

**Do not state that private code or commercial business automatically triggers an OEM fee.** If AGPL permission covers the relevant activity and the conditions are satisfied, that activity can be free. A proprietary service or external API integration may be a separate work depending on the actual combination; no broad legal conclusion is promised.

The independent Editor additional-permission draft has not yet been adopted. [Commercial Licensing](COMMERCIAL-LICENSING.md), [Historical MIT](docs/legacy-mit.md), [Third-party licenses](LICENSE-SCOPE.md).
