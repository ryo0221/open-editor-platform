# ladder-core (SL6, PLC ladder program)

Private pure TypeScript model of a PLC ladder program for the circuit domain of the circuit simulation plan and ADR 021 (addendum). IEC 61131-3 Ladder Diagram with IEC variable names (SL-U4); no vendor device numbers. No DOM, React or Worker, and no import of another package.

- `model.ts`: `LadderDocument` (schema 1): name, scan period (`scanMs`), variables (`BOOL`, `INT`, `TIME`, and instances of `TON`/`TOF`/`TP`/`CTU`/`CTD`; role input, output or internal) and rungs. A rung is a network of nodes (NO/NC/rising/falling contacts, series, parallel, timer, counter and compare boxes) from the left rail, ending in coils (normal, negated, set, reset) in parallel. Every node and coil has an ID.
- `validateLadder(unknown)`: strict plain-JSON validation with paths: exact keys, IEC identifiers (no keywords; names compare without case), types of every reference, coils never on inputs, one use per block instance, parallel nodes of two or more branches, a coil on every rung, initial values and presets in range, initial safety limits (`limit-*`, not performance promises). Warning `coil-duplicate` (two plain coils on one variable).
- `ladderScan(doc, state, inputs, forced)`: one scan (inputs in, rungs from the top, a later rung sees an earlier rung's coils), with IEC semantics for edge contacts, TON/TOF/TP and CTU/CTD. Time is virtual (`scanMs` per scan). Returns the new state and the power leaving every node and coil. `ladderInitialState`, `ladderOutputs`, `ladderRun`.
- `plcopen.ts`: PLCopen TC6 XML (v2.01). `ladderToPlcopen(doc)` writes one `program` POU with an `LD` body (each rung its own rails; a parallel is a wired OR; timers, counters and compares as `block`s fed by `inVariable`s; the scan period as the task interval), and refuses (`plcopen-unsupported`, or the reader's limit such as `limit-xml-size`) any file that would not read back as the same program. `ladderFromPlcopen(xml)` reads that back, rebuilding the series / parallel tree from the connections (common leading elements factored out; a bypass is put back together by matching the paths through it), and refuses anything else as `plcopen-unsupported` (`plcopen-shape` for a non-PLCopen document, `plcopen-invalid` when the result fails `validateLadder`). `ladderCanonical(doc)` is the form it reads back: IDs renumbered in order, nested series / parallels flattened, repeated empty branches dropped, variables grouped by role. Variable `address`es and element positions are not kept. `xml.ts` is the small reader it uses (no DOCTYPE, only predefined entities and character references, initial safety limits `ladderXmlLimits`).
- `edit.ts` (SL7a): `applyLadderOperation` (program, rung and variable operations and `batch`; a rename renames every reference; the result is validated as a whole, so a variable still in use cannot be deleted) and rung helpers for the screen (`ladderInsertSeries`, `ladderAddBranch`, `ladderRemove`, `ladderMove`, `ladderReplace`, `ladderNormalize`): nested series and parallels are merged and the IDs of what stays are kept. `ladderNewId` gives random IDs no element uses.
- `fixtures.ts`: self-hold, blink (two TONs) and counter examples, written for this project.

Not yet here: the screen (SL7b), coupling to the schematic (SL8). See the verification record.
