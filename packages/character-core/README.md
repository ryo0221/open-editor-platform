# character-core (Character C1, pure model)

Private pure TypeScript model for the [Character design](../../docs/character/README.md) and ADR 019. Accepted as a regular editor on 2026-11-14 (record); schema 1 is the stored format, the exports are pre-1.0 and not a stable public API. No DOM, React, Worker or kernel, and no import of any CAD or BIM package (ESLint).

- `model.ts`: `schemaVersion: 1` types, the only schema (`CharacterDocument`: assets, materials, parts, skeletons, skins, morphs, actions), millimetres, right-handed Z-up, 240,000 ticks per second. Mesh data is never in the content: each part names a `mesh-epm` asset (`@editor-platform/geometry-mesh`) by ID, SHA-256 and length; the Host keeps the bytes. Transforms are T · R · S with unit quaternions. A skin binds a part's mesh to a skeleton with an inverse bind matrix per weighted bone (glTF's rule: the part's own transform does not move skinned vertices). Tracks target a part's or bone's translation, rotation or scale, or a morph's weight; keys carry Animation's easing (ADR 012). `characterLimits` holds the initial limits.
- `validateCharacter(unknown)`: strict plain-JSON validation with path diagnostics: exact keys, one ID namespace, references by kind, part and bone cycles, unit quaternions, non-zero scales, sorted keys inside the action, value shapes per property, easing ranges. Schema 1 only (`unsupported-schema`). `checkCharacterMeshes(doc, meshes)` adds the checks that need decoded meshes: material slots, skin bones and morph IDs.
- `evaluate.ts`: `poseAt(doc, action, tick)` samples every track (vectors and weights through `easingProgress`, rotations by slerp, clamped to the action); `worldMatrices`, `skinMatrices` (joint order of the mesh's `boneIds`) and `skinnedPositions` (linear blend skinning with every weight).
- `operations.ts`: C1's edits (rename, rename a bone, show or hide a part) as `applyCharacterOperation` and `characterEditorCommand`, one EditorSession transaction that re-checks the base hash, authority and the whole document.
- `fixtures.ts`: `blockyFigure()` (F-C1), a generated figure of 11 boxes and 11 bones with two materials, a morph and two actions, with its EPM bytes.
- `gltf.ts`: `importGltf(bytes)` reads GLB, `.vrm` or glTF JSON whose buffers and images are `data:` URIs into a validated schema 1 document, its EPM and image assets, a sorted list of losses and VRM 0/1 metadata (licence fields shown, not enforced). Metres Y-up become millimetres Z-up; UV v is flipped; colour factors go from linear to sRGB; primitives are welded per node; parts keep their nearest part ancestor as parent and bones their nearest joint, with the static nodes between folded into both the rest pose and the keys; a node's morph weights override its mesh's; sparse accessors are read as dense data; skins that share joints become one skeleton, parents first, and a skeleton whose roots sit under one mesh node follows that part; mirroring scales keep their sign on the authored axis; transforms TRS cannot hold (shear), keys that need other components (`coupled-key`) and authored normals the rebuilt ones do not match (`authored-normals`), texture sampling other than repeat/linear (`texture-sampler`), normal scale or occlusion strength other than 1 (`texture-strength`), blending by a colour texture's alpha (`alpha-texture`), morph normal or tangent deltas (`morph-normals`) and material extensions read past (`extension:<name>`) are losses; without `NORMAL`, every face keeps its own corners and stays flat; a primitive without a material gets glTF's default (white, metallic 1, rough 1); STEP keys hold; CUBICSPLINE keeps values only (a loss). IDs come from `extras.ep_id`, else from the node name (its name path when names repeat; past 128 code points shortened with a SHA-256 digest). External URIs, Draco and other unknown required extensions, broken containers, non-PNG/JPEG images, duplicate IDs and files past `gltfImportLimits` (including a budget on decoded accessor values, checked before allocating) or `characterLimits` are refused whole (`GltfImportError`).
- `ids.ts`: `characterElements(doc)` and `diffCharacterIds(before, after)` list parts, bones, morphs, materials and actions as added, removed, changed or kept by ID (a morph is changed when its part's mesh asset changed), so a re-import can show what the references point to now (nothing is rewritten).
- `gltf-fixtures.ts` (tests only): a generated 1 m skinned bar with a morph, a texture and an animation; no outside model is committed. `CHARACTER_GLTF_CORPUS=<dir>` runs the importer over sample files in a folder.
