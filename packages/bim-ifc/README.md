# bim-ifc (R2c-4a export, R2c-4b import)

Private IFC adapter for the building (BIM) domain of the R2c design. Not a registered editor or a stable public API. It holds a self-written ISO 10303-21 writer (ADR 018 proposes the self-written codec over web-ifc and IfcOpenShell) and maps `bim-core`'s derived shapes and quantities to IFC4 ADD2 TC1 entities. It has no external dependency beyond `@noble/hashes`, and no import of any CAD package. It reads with `geometry-core`'s P21 reader.

- `p21.ts`: the P21 writer. Values in exchange form (`formatReal` always has a decimal point and keeps the shortest round-trip digits; `formatString` doubles `'` and `\` and writes anything outside printable ASCII as `\X2\…\X0\`), the header, and GlobalIds (`compressGuid`, the 22-character form; `stableGuid`, a SHA-256-based ID that is the same for the same key).
- `writeIfc(doc, options)`: validates the document (`invalid-document`), then writes the spatial structure (project, site, building, one storey per level; spaces aggregated under their storey, other elements contained in it), mm/m²/m³/rad units, `Body` and `Axis` contexts, types with `IfcRelDefinesByType` (doors and windows share one `IfcRepresentationMap`), material layer sets and profile sets with their usages, walls (`IfcIndexedPolyCurve` profiles with arcs, axis curves), slabs with holes, columns and beams with parametric profiles, openings (`IfcRelVoidsElement`) and the openings doors and windows fill (`IfcRelFillsElement`), flat and mono-pitch roofs, spaces, parts (`IfcFacetedBrep` or `IfcShellBasedSurfaceModel` from a supplied export mesh, with `EP_PartReference`), joins (`IfcRelConnectsPathElements`), `Pset_*Common`, user property sets, `Qto_*BaseQuantities` and `EP_Constraints` (level, offset, grid and roof references, and the values the shapes normalize: points, loops with their bulges, roof form, opening sizes, window sills, unnamed elements). Materials carry their ID in `IfcMaterialProperties`; user property set definitions are `IfcPropertySetTemplate`s (ID in `Description`) tied to their sets with `IfcRelDefinesByTemplate`; grid axes, joins and views are complex properties in the project's `EP_Grids`, `EP_Joins` and `EP_Views`, and true north is the project's `EP_Constraints.TrueNorth`. Elements clipped by a roof are `IfcBooleanClippingResult`s of the extrusion and the roof's underside half-space.
- Clipped elements keep only plan quantities from the analysis (a wall's length, width and footprint, a column's section); the rest come from `kernelQuantities`.
- A part mesh is split into bodies joined across edges two triangles share, one shell each (an `IfcClosedShell` must be connected). An inward-facing body is a cavity, cut from the smallest body it lies inside (ray parity in three directions) with an `IfcBooleanResult` (`CSG`); a cavity outside every body is refused (`part-cavity`).
- Refusals: a clipped element without kernel quantities or a part without a mesh (`evaluation-required`), a part mixing solids and sheets (`part-mixed-kinds`), a GlobalId used twice, as when two elements keep the same imported GlobalId (`global-id-duplicate`).
- Same input, same bytes: GlobalIds come from the Artifact ID and each entity's ID (an element's kept `ifcGlobalId` wins), and the only time is the saved version's time stamp.

- `readIfc(bytes, { resolvePart, acceptLoss })` (`import.ts`): IFC4 only, within `bimIfcImportLimits` (16 MiB, 2,000,000 instances, nesting 32). Elements with `EP_Constraints` in a mm/rad file come back from `EP_*` exactly (GlobalIds kept as `ifcGlobalId`), then the document is written again (`writeIfcShapes`) and each restored element's world placement and `Body` items are compared with the file's (`constraint-mismatch`). Other programs' elements come in at fixed heights and coordinates ("without follow", counted in the report): rectangular-footprint walls, slabs with holes, columns and beams with parametric profiles (no fillets), flat roofs, spaces, openings that are wall-aligned boxes or slab-piercing extrusions, types (layers or profiles, else made from the material and thickness), storeys, `IfcGrid` axes with `IfcGridPlacement` columns, `IfcRelConnectsPathElements` joins, and `clipBy` when a wall's horizontal half-space is a flat roof's underside. Everything else is listed in the loss report (entity, reason, GlobalId, name); with losses, nothing is returned until `acceptLoss`. Parts need their CAD version to resolve (`resolvePart`). Refusals: `ifc-schema-unsupported`, `ifc-unreadable`, `ifc-too-large`, `ifc-too-many-entities`, `ifc-too-deep`, `ifc-unit-unsupported`, `ifc-no-project`, `constraint-mismatch`, `invalid-document`.

Columns at grid intersections use `IfcLocalPlacement`, with the intersection in `EP_Constraints`: IfcOpenShell 0.9 cannot place an IFC4 `IfcGridPlacement`. `scripts/bim-ifc/verify.py` checks written files with IfcOpenShell in the verification environment; `scripts/bim-ifc/foreign.py` wrote the IfcOpenShell-authored import fixture (`fixtures/f35-ifcopenshell.ifc`), next to the hand-written `fixtures/f35-foreign.ifc`. See the verification records for export and import.
