# geometry-view (shared display, R2c-3b)

Private package of the R2c design (R2bとの境界) and ADR 017: the display parts CAD and the building domain (`bim`) share, so that neither depends on the other. Not a registered editor or a stable public API. Depends on `geometry-core` and Three.js, and (for the shared texture panel, #662) on `editor-ui`, React and fflate; never on a CAD or bim package (ESLint and `geometry-kernel.test.ts` check it).

- `instances.ts`: moved from `packages/cad/src/assembly-view.ts` without changing behaviour. `instancesGroup(solids)` draws every instance of one solid from one set of buffers: one `InstancedMesh` per mesh (a sheet also from its back, in a darker tint), its outline per instance, and a solid without meshes as a faint box from its bounds (`pending`, `simplified`, `unavailable` colours; `dim` fades a reference display). `instancePath(hit)` gives the path of the instance a ray hit (surface or outline); `userData.mesh` and `userData.frames` let a domain pick on the solid's own mesh at the instance's frame (CAD's connectors). `poseInstances(group, moves, delta)` moves the instances under `moves` by their matrices only (a drag preview), `movedKey` says when such a preview still holds, `instancesBytes` counts the GPU buffers once each for the display budget, and `disposeInstances` frees them. R2b-4 (LOD): a solid may carry `coarse` meshes, and `instancesGroup(solids, level)` draws each instance at its `ViewLevel`: the standard meshes, the coarse ones (no outlines and no `userData.mesh`, so a domain does not pick on them), or a solid box in the solid's colour; a level the solid lacks draws with the meshes it has. `lodLevel(px, previous)` chooses the level from an instance's size on screen (`viewLod`: standard from 64 px, coarse from 8 px, kept within × or ÷ 1.25 of a threshold).

- `lighting.ts` (#665, #661): `ViewLighting`, the standard or the realistic lighting of one scene, and `setViewFinish` for a look's roughness and metalness.
- `textures.ts` (#662): `setViewTextures(material, set)` puts a texture set's decoded images on a solid's material, each a copy that repeats every `sizeMm` along the mesh's real-size `uvs` (turned by `rotationRad`; a DirectX normal map is drawn with its green flipped); as in glTF, the material's colour, roughness and metalness multiply the maps. `ViewTextureCache` decodes each image once by hash (`createImageBitmap`) and calls back when one is ready. `viewTextureBytes` counts each image once with its mipmaps for the GPU budget, and `instancesBytes` includes it. `disposeViewTextures` frees the copies (`disposeInstances` does it). `viewTexturesOf(set, assets, cache, read)` turns a stored set (`GeometryTextureSet`, asset IDs by map) into a drawable one.
- `texture-files.ts` (#662): `readTextureFiles` reads a downloaded zip (fflate) or images, checks each image's size and decides its map from the file name (`geometryTextureFileRole`); with two maps of one kind it keeps the OpenGL normal map.
- `texture-panel.tsx` (#662): `TextureEditor`, the texture part of an appearance section that CAD bodies and bim materials share: the import dialog (map per file, name, real size, normal convention, source URL, licence) and the set's size, turn, convention, replace and remove. The domain stores the images (`onAdd`) and the edits (`onChange`).

CAD keeps its names (`partsGroup`, `partPath`, `poseParts`, `partsBytes`, `disposeParts`, `ViewportPart`) as aliases in `assembly-view.ts`. LOD, progressive display and the cache budget (R2b-4) are to be written here.
