# simulation-core (structural analysis of CAD parts, ADR 020)

Private package of the R3 analysis design and ADR 020. Not a registered editor or a stable public API. Pure model: no React, no kernel, no Worker. It reads CAD only through `@editor-platform/cad-core`'s public entrypoint (the F1 reference type and fixtures).

- `model.ts` (R3a): `SimulationDocument` schema 1, a separate artifact that fixes one solid body of one CAD version (`source`: artifact, version, content hash, body). Units are the one consistent set mm–N–MPa–t–s. Materials are linear elastic and isotropic (`simulationMaterialPresets` for steel, aluminium, stainless steel, titanium). Loads are a total force on faces or edges, a pressure on faces and gravity; constraints are fixed, roller (normal displacement only) and given displacements. Targets are `{ kind: 'face' | 'edge', ref: CadTopologyRef }` on the body's result feature. Preparation (hole and fillet thresholds, explicit faces) and mesh settings (tet10 only, size, minimum size, grading, local sizes) are stored for R3b–R3c. Studies are linear static, or modal (R3g-2: `modes` from 1 to `simulationLimits.modes`, no loads, metric `first-frequency`); or thermal (R3h-2: held temperatures as constraints, heat fluxes and convections as loads, each kind of study taking only its own items, held by a temperature or a convection; metrics `max-temperature` and `max-heat-flux`). A material's `conductivity` (W/(m·K), the same number as mW/(mm·K)) is optional and needed by a thermal run; the presets carry one. `simulationLimits` holds the initial safety limits.
- `validation.ts`: `validateSimulation(value)` checks plain JSON (depth, finite numbers, no accessors or reserved keys), schema 1 only (`unsupported-schema`), every key and value, one ID namespace (`duplicate-id`), retired IDs (`retired-id-in-use`), references between studies, loads, constraints and the material. Whether a target resolves on the evaluated shape is decided by evaluation (R3c), never here.
- `operations.ts`: `applySimulationOperation` (one operation on a copy, then the whole document is validated; nothing is half-applied) and `simulationEditorCommand`, one ordinary `EditorSession` command that re-checks the base hash (`simulation-base-mismatch`) and the edit authority (`permission-denied`). Removing a load or a constraint drops it from every study in the same edit; a removed ID is retired and never given again (`freshSimulationId`). A material the body uses is not removed (`material-in-use`).
- `source.ts`: `checkSimulationSource(doc, cad)` reports what the source CAD document alone tells: the body is missing, consumed or not a solid, or a target names another feature than the body's result feature. `simulationTargets(doc)` lists every stored target with its path.
- `fixtures.ts`: `simulationFixture()`, the F02 plate fixed at one end with 500 N on the other.
- `mapping.ts` (R3c-1): `buildMapping(doc, table, history, mesh, context)`, the mapping table of every stored target: CAD face/edge by F1 (`resolveTopologyRef` on the body's topology table) → analysis shape by the preparation's kernel history (`PreparationHistory`: per CAD element, deleted or the analysis elements it became) → mesh (`MeshPresence`). Rows are resolved, ambiguous (`cad-ambiguous`, `split-by-preparation`, `merged-by-preparation`) or missing (`cad-missing`, `removed-by-preparation`, `not-meshed`), with the stage and the analysis elements or candidates. Nearness is never used. `mappingReady(rows)` is true only when every row resolved. A stored re-selection (`overrides`, set with `setOverride`, removed with `clearOverrides`) decides a split or merge only for the same version, preparation hash and kernel build and only among the candidates; it is refused for a target its owner does not hold (`override-target`) and dropped in the same edit when the owner stops holding it. `checkLoadApplication` compares each load's nodal force sum with the request and its mesh area or length with the analysis shape's (`loadApplicationTolerance`: force 1e-9, area and length 0.5 %), and that each constraint holds a node.
- R3i-4: a linear static or modal study may set `idealisation` (`solid` when absent, or `shell`: triangles on the body's midsurface); a thermal study may not. The `pinned` constraint holds every displacement and leaves the rotations free, holding as `fixed` does on a solid. `buildMapping` with a `midsurface` history maps a wall face (and its partner, `reversed`) to its midsurface face and a side of the wall to the midsurface edges it runs along (`as: 'edge'`), never ambiguous by design; an element with no image is `off-midsurface`.
